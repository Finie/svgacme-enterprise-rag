# Derived knowledge model

knowledge_chunks is a rebuildable projection of PostgreSQL policies, policy_sections and explicitly selected scenarios. Documents are logical, not a second persisted copy of sources. POLICY document identity is POLICY:<policy_id>; SCENARIO identity is SCENARIO:<scenario_id>.

Each chunk has id, document_type, source_id, policy_id, policy_section_ordinal, scenario_id, chunk_index, content, metadata (JSONB), content_hash, chunking_version, created_at and updated_at. The existing composite policy section identity (policy_id, section_ordinal) replaces the proposed standalone policy_section_id; no synthetic section foreign key is introduced. Metadata exposes that composite locator as policy_section_id for consumers.

A CHECK requires POLICY rows to have source_id = policy_id and a section ordinal, with scenario_id NULL. SCENARIO rows require source_id = scenario_id and both policy fields NULL. Typed foreign keys enforce provenance; section membership is enforced by a composite FK. Source deletions cascade only to these derived chunks. Unique(document_type, source_id, chunk_index) prevents duplicate logical positions; chunk_index is zero-based across a document. IDs use source, section/block and local chunk position, allowing unchanged later sections to retain IDs. Indexes support source type, policy, section, scenario and content hash filtering. Embeddings are stored separately as described below; no ANN vector index is needed.

## Embedding projection

knowledge_chunk_embeddings is a 1:N child of knowledge_chunks. Its natural primary key is (chunk_id, embedding_provider, embedding_model, embedding_version). Each row contains embedding_dimensions, embedding vector(1536), embedded_at, content_hash_at_embedding and chunking_version_at_embedding. The configured space is Google gemini-embedding-001, truncated from its native 3072 dimensions to 1536 via the API's `outputDimensionality` field to match this column; OpenAI text-embedding-3-small/large remain available as an alternate same-dimension provider (see docs/embeddings/provider.md). CHECK constraints enforce dimensions=1536, vector length, nonzero norm, hash shape and nonempty model/version/provider. Foreign keys cascade on removal of a chunk. There is one current content snapshot per chunk/provider/model/version; versions/models/providers can coexist, old content within a version is replaced, not archived.

Only POLICY chunks with real policy/section references are eligible in this phase, even if scenarios were selected for knowledge ingestion. Search always chooses one exact provider/model/version/dimension space and checks both current content hash and chunking version. No operational rows or evaluation answers enter the embedding corpus. Dimension changes require a deliberate vector column/check migration and full new-space embedding build; never resize/pad real provider vectors.

The chunk logical-position UNIQUE constraint becomes DEFERRABLE INITIALLY IMMEDIATE, permitting an atomic reorder with stable IDs. Knowledge rebuild updates existing chunks instead of delete/reinsert, preserving embeddings across metadata-only changes. Changed content/version leaves a stale embedding detectable and excluded by retrieval until re-embedded. Deleted chunks still cascade. No ANN index at this scale; exact cosine distance uses pgvector <=>.
