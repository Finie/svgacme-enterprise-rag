# Embedding lifecycle

A row is reusable only if chunk ID, provider, model, dimensions, embedding version, content hash and chunking version all match. All generation and search queries use these predicates. Existence alone never implies freshness. Changing a model/version creates another space; changing source content replaces the current row for that space on rebuild. Historical models may remain stale and are never returned by current-space retrieval.

The builder snapshots pending IDs, divides them into configurable batches and commits each successful batch. A per-space PostgreSQL advisory transaction lock serializes concurrent builders. Pending rows are rechecked after obtaining that lock, and source chunk rows are held with FOR SHARE during the provider request and persistence. The batch transaction timeout includes the bounded network/retry budget. This favors correctness at the current corpus size; it can briefly block a knowledge rebuild and is not intended as a high-throughput work queue. A final conditional INSERT checks hash/version/eligibility again. Upsert by natural key prevents duplicate rows. A failed batch rolls back; earlier batches remain valid. Rerunning skips committed rows. Fail-fast output distinguishes failed batch rows from unprocessed rows.

Dry-run takes no advisory lock, writes nothing and makes no API call. It reports eligible/pending/skipped counts, space and batch size. A real second run with no changes reports zero API calls and retains embedded_at.

Knowledge rebuilds update stable IDs in place. Their logical-position UNIQUE constraint is deferrable so ordering can change atomically without deleting unchanged evidence. Metadata-only updates preserve embeddings; hash/chunking-version changes make them stale, and deleting a source chunk cascades its embeddings. Version the embedding input contract whenever input construction or processing semantics change.

`embeddings:validate` is entirely local. It checks FK resolution, vector dimensions/norm, metadata and hash shape, policy eligibility and counts stale records across spaces. Stale historical rows are reported, not treated as corruption. The schema primary key enforces uniqueness. `--require-complete` additionally rejects missing/stale entries in the configured active space and an empty eligible corpus. The existing database and knowledge validators remain independent of provider credentials.
